# 梁元·月食输出监管

## 安装

需要 SillyTavern 1.18.0 或更高版本。在 SillyTavern 的扩展管理界面安装本扩展（或将本目录放入用户扩展目录），刷新后在扩展面板启用“梁元·月食输出监管”。本扩展只匹配包含 `LUNAR_OUTPUT_GUARD_V2_5` 标记且在 `prompt_order` 中启用的 2.5 预设，不会接管旧版预设。

扩展默认只在检测到预设内容包含“梁元·月食”时运行。它不调用额外 API。

## 工作方式

- 在 `MESSAGE_RECEIVED` 的首个监听器中同步把候选隔离为安全错误文本，再由宿主继续渲染；不依赖隐藏历史楼层；
- 角色卡原生首句 `first_message` 不经过字数与正文合同校验，避免导入后首句被误伤；
- 生成前强制要求“显示思考”保持关闭，预设把 reasoning effort 固定为 `minimal` 兜底，消息入场时同步清除原生 reasoning 面板数据；
- 合法回复在宿主渲染后以短段落节奏渐显；结束时从当前消息重新渲染，不复用可能已经过期的 HTML；
- 收到回复后检查唯一 `<content>`、3200–3600 去空白字符、核心禁词、核心套话、破折号、重复段落和思考泄漏；
- 通过后由扩展补上唯一 `<CONTENT_BOUNDARY/>`，再按已确认适配器追加状态栏；状态占位符和审计块均由模型禁止输出；
- 支持实际 MVU 协议 `<UpdateVariable><Analysis>…</Analysis><JSONPatch>…</JSONPatch></UpdateVariable>`；当角色卡声明这组固定包装时，严格要求唯一 `Analysis` 后紧跟唯一 `JSONPatch`，不允许缺失、重复、改名或夹带裸文字；其他卡仍可由适配器声明“外层标签内直接放数组”；
- 变量更新必须是合法 JSON Patch，路径、类型和操作必须来自已确认的适配器；变量块只能位于正文之后，所有已登记外层标签合计最多一块；
- 若角色卡明确要求每次回复提交变量块，扫描后将此要求锁入适配器，缺块直接拒绝；
- 有变量块时等待 `Mvu.events.VARIABLE_UPDATE_ENDED`，比对更新前后状态并逐条确认操作确实生效，拒绝整块空更新、混合在有效操作中的同值更新以及未按声明生效的操作；拒绝时会事务性回滚本轮 MVU 改动；
- 通过后再确认新变量已写入当前消息楼层，然后刷新和放行状态栏。超时则回滚并显示本地错误，不让旧状态栏冒充新状态；
- 失败候选先替换为安全错误文本，只有确认它仍是聊天末尾的监管候选时才允许重试，最多两次；
- 连续失败时只保留错误文本，不保留原始违规正文。

有状态角色卡需要酒馆助手/MVU，但不需要额外模型 API。首次使用先等待角色卡变量初始化，再点“扫描当前角色卡与实时 MVU Schema”：扩展从当前消息楼层的 `Mvu.getMvuData()` 读取真实路径和类型，不再从角色卡示例文字猜白名单。核对状态栏模板、变量外层标签、JSON Patch 内层标签、允许操作、路径与类型后，确认并锁定适配器。0.5.0 会使旧适配器失效，必须重新扫描并确认一次。未确认、协议缺项、MVU 未就绪或 Schema 改变都会在生成前停止放行。无状态角色卡不要求适配器。

监管启用时禁止 Continue，因为 Continue 会把已批准旧正文和续写合并成同一候选，无法满足“一轮唯一终稿”合同；请发送新消息、重新生成或新建 swipe。

## 版本边界

扩展使用 SillyTavern 的公开上下文 API，并要求支持 `eventSource.makeFirst`。有状态卡还要求酒馆助手/MVU 提供 `Mvu.getMvuData`、`Mvu.replaceMvuData`、`Mvu.events.VARIABLE_UPDATE_ENDED` 和 `eventOn`。首次安装后仍须在真实酒馆测试：失败回复是否没有可见正文、重试次数是否停止、变量是否写入当前楼层、拒绝楼层是否回滚变量、状态栏是否显示同层新值。通过本地测试只代表具备实测条件，不等于真实运行时已经验收。

“不产生独立思考内容”的强保证以 SillyTavern 1.18+ 的 DeepSeek 直连接口为验收范围：关闭“显示思考”后，宿主会向该后端发送禁用 thinking 的参数。`minimal` 只作为其他兼容接口的最低强度兜底；OpenRouter、自定义代理或其他后端是否真正停止内部推理取决于其是否执行该参数，扩展只能阻止生成、清除面板数据并拒绝泄漏，不能证明远端服务没有私下消耗 reasoning token。
